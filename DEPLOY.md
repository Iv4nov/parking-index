# Публикация — GitHub → Vercel → Neon Postgres

## Структура проекта (важно понимать, прежде чем начинать)

```
site/
  index.html, manifest.json, sw.js, icons/   ← сам сайт, отдаётся статикой
  api/
    index.py        ← бэкенд, ОДНА serverless-функция на все запросы /api/*
    lib/
      models.py, index_calc.py               ← общий код, НЕ отдельные функции
  scripts/           ← локальные инструменты сбора данных, НЕ деплоятся
  requirements.txt   ← зависимости бэкенда для Vercel
  vercel.json        ← правила маршрутизации
```

Почему так: Vercel — serverless, бэкенд не может держать файл SQLite между
запросами (диск не переживает завершение функции). Поэтому база данных —
не файл рядом с кодом, а отдельная облачная Postgres (Neon, бесплатно).

## Шаг 1 — GitHub

1. Создай новый пустой репозиторий на github.com (публичный или приватный — не важно)
2. Загрузи в него содержимое папки `site/` целиком (через `git init` / `git add` / `git commit` / `git push`, либо просто перетащи файлы через веб-интерфейс GitHub — для одного раза это тоже нормально)

## Шаг 2 — Подключи репозиторий к Vercel

1. Зайди на vercel.com, войди через GitHub-аккаунт
2. "Add New" → "Project" → выбери свой репозиторий
3. Framework Preset — оставь "Other" (это не React/Next.js, просто статика + Python-функция)
4. Нажми Deploy — на этом шаге сайт задеплоится, но бэкенд ещё не будет работать (нет базы данных)

## Шаг 3 — Подключи бесплатную Neon Postgres

1. В панели проекта на Vercel — вкладка **Storage**
2. "Create Database" → выбери **Neon** (бесплатный тариф, без карты)
3. После создания Vercel сам добавит переменную окружения `DATABASE_URL` в проект — руками ничего вписывать не нужно
4. Передеплой (Vercel обычно предлагает это сделать сам после подключения базы; если нет — Deployments → на последнем деплое "..." → Redeploy)

## Шаг 4 — Засей базу данными (со своего компьютера)

Тебе нужна строка подключения к базе — Vercel → Storage → твоя база Neon → там будет `DATABASE_URL`, скопируй её.

```
cd site
pip install -r requirements.txt -r scripts/requirements.txt --break-system-packages

set DATABASE_URL=<вставь строку подключения от Neon>
set MOS_DATA_API_KEY=2d2c61c7e2f1364ee44f7d6f38223322

cd scripts
python parking_zones.py
python metro_stations.py
move metro_stations.json ..\api\metro_stations.json
cd ..\scripts
python seed_zones.py parking_zones_sadovoe.geojson
```

Последняя команда напишет "Загружено/обновлено зон: ..." — это значит данные
теперь в облачной базе, не на твоём компьютере.

## Шаг 5 — Проверка

Открой адрес, который выдал Vercel (что-то вроде `https://твой-проект.vercel.app`)
— это и есть публичный сайт, открытый для всех, с телефона и с компьютера.

Проверь: `https://твой-проект.vercel.app/api/health` — должен ответить `{"status":"ok"}`.
Если это работает, но сама карта пустая — скорее всего забыт шаг 4 (сидирование базы).

## Локальная разработка (после публикации, для дальнейших правок)

```
cd site\api
uvicorn index:app --reload --port 8000
```
(команду нужно запускать именно из папки `api`, иначе не найдутся модули из `lib/`)

Второе окно:
```
cd site
python -m http.server 5500
```
Открой `http://localhost:5500` — фронтенд сам поймёт, что это локальный запуск,
и обратится к `localhost:8000`, а не к продовому бэкенду.

## Что стоит сделать после первого успешного запуска (не блокирует публикацию)

- **Сузить CORS** в `api/index.py` (сейчас `allow_origins=["*"]`) — заменить на
  реальный адрес твоего сайта, когда он будет известен после первого деплоя
- **Периодическое обновление зон** — сейчас `parking_zones.py`/`seed_zones.py`
  запускаются вручную; со временем стоит поставить это на регулярный запуск
  (например, раз в месяц), чтобы данные не устаревали
- **Реальные даты школьных каникул на 2026-2027 год** — в `api/index.py`
  захардкожены даты только на 2025-2026 учебный год, нужно будет обновить
